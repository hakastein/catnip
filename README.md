# catnip

CLI для агентов: просмотр и правка файлов, сцепляемые в bash. `catnip show` печатает файл, диапазон или окрестность
позиции с номерами строк; `catnip edit` применяет пакет правок к нескольким файлам и сначала проверяет все правки,
так что несошедшаяся правка не записывает ни одного файла; `catnip write` создаёт файл из stdin. После записи
catnip запускает фиксеры и проверки из конфига и сообщает результат кодом выхода.

Как агенту пользоваться командами — [`skills/catnip/SKILL.md`](skills/catnip/SKILL.md).

## Установка

```bash
make build                                   # bin/catnip, статический, без CGO
install -m 755 bin/catnip ~/.local/bin/catnip
```

Скилл `skills/catnip/SKILL.md` копируется в каталог скиллов харнесса. Сборка — Linux, macOS, Windows
(`bin/catnip.exe`: `GOOS=windows make build`). Фиксеры и проверки идут через `sh`, на Windows — из Git for Windows в
`PATH`.

## Конфиг

Глобальный — `catnip/config.json` в каталоге конфигов пользователя: `$XDG_CONFIG_HOME` или `~/.config` на Linux,
`~/Library/Application Support` на macOS, `%AppData%` на Windows. Проектный — `.catnip.json` в корне
git-репозитория текущего каталога.

```json
{
  "*.go": {"fix": ["gofmt -w {file}"], "check": ["go vet {file}"]},
  "*.php": {"check": ["php -l {file}"]},
  "src/legacy/*.php": {}
}
```

- Ключ — glob. Glob без `/` сравнивается с именем файла, с `/` — с путём от корня репозитория (`*` не переходит
  через `/`).
- `fix` может менять файл, `check` не должен. Сначала фиксеры, потом проверки; команды идут через `sh -c` в
  текущем каталоге с окружением catnip, `{file}` заменяется путём в кавычках.
- Правило проекта заменяет глобальное правило с тем же glob целиком; пустое правило `{}` отключает его.
- Неизвестное поле, битый JSON или glob, пустая команда, недоступный каталог конфигов — код выхода 2, ничего не
  записано.
- Проектный конфиг исполняется так же, как `Makefile` и тесты репозитория: catnip доверяет ему, как агент доверяет
  `make test` в той же рабочей копии.

## Коды выхода

| Код | Значение |
|---|---|
| 0 | записано, проверки прошли |
| 1 | ничего не записано: правка не сошлась, файла нет, ошибка ввода-вывода |
| 2 | ошибка аргументов или конфига |
| 3 | записано, но проверка или фиксер упали, либо пакет записан не целиком |

## Ограничения

- Каждый файл пишется атомарно: временный файл и rename. Сохраняются права, включая setuid, setgid и sticky, и
  цель симлинка; симлинк на отсутствующий файл — ошибка. Владелец и расширенные атрибуты не сохраняются. Файл с
  несколькими жёсткими ссылками на Linux и macOS перезаписывается на месте, не атомарно, чтобы новое содержимое
  видели все ссылки; на Windows такой файл отвязывается от остальных ссылок. На Windows из прав есть только
  атрибут «только для чтения».
- Пакет из нескольких файлов не атомарен: сбой записи между файлами оставляет часть записанной, catnip
  перечисляет записанные и выходит с кодом 3.
- В пакете текст не может содержать строку, начинающуюся с `@@@ `.
- Текст пакета — целые строки, поэтому последнюю строку без перевода строки пакет текстом не найдёт: для неё —
  цель по строке (`путь:N#хеш`) или правка аргументами.
- CRLF понимается, только если им кончается каждая строка файла; в файле со смешанными окончаниями текст с `\n`
  совпадает лишь с LF-строками.

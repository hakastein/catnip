# Changelog

## v0.9.0

- `catnip edit` и `catnip write` берут флаг `--skip-checks` перед путём: файл записывается и печатается его diff,
  фиксеры и проверки не запускаются, код 0.

## v0.8.0

- `catnip show` берёт несколько целей: каждая печатается блоком после строки цели как она задана, блоки разделены
  пустой строкой; цель, которую не напечатать, — причина в stderr, остальные печатаются, код 1.
- `catnip show <путь>:<от>-<до>` с концом диапазона за концом файла печатает строки до последней и предупреждение в
  stderr, код 0; начало диапазона или позиция за концом файла — ошибка, как раньше.
- `catnip show --rev <ревизия>` печатает файл таким, каким он был в ревизии git, с адресами строк и `--blame` этой
  ревизии; с `::<символ>` и `--outline` — ошибка аргументов.
- Скилл `catnip`: описание до 60 символов; раздел навигации сразу после просмотра сопоставляет формы grep (тело
  функции, использования одного и нескольких имён, реализации интерфейса) с `def --body` и `ref` по имени.

## v0.7.0

- `catnip rename <позиция> <выражение> <новое имя>`: переименование символа Go во всех файлах проекта, под linux,
  darwin и windows, с методами типов, приводимых к интерфейсу. Все правки проверяются до записи; отказ agent-lsp
  (конфликт имён, символ вне проекта, старое имя в файле, который не собирает ни одна платформа, пакет) — код 1,
  ничего не записано. Каждый файл пишется целиком, как у `edit`, с BOM и окончаниями строк; затем по каждому — его
  diff, фиксеры и проверки из конфига. Упавшая запись или проверка — код 3 и в stderr `written: <файлы>`.

## v0.6.0

- `catnip ref`: использования символа Go и, после строки `implementations:`, реализации интерфейса или его метода —
  по тем же вопросам, что у `def`, строками `путь:N#hash: текст`. Файлы — по убыванию числа строк; несколько мест на
  строке — одна строка; `--limit` (по умолчанию 60 строк) даёт сначала по строке на файл,
  непоместившееся — строкой `<n> more lines in <m> files`. Использования собираются под linux, darwin и windows.
  Имя с несколькими объявлениями — вопрос без ответа со списком их адресов.

## v0.5.0

- `catnip show <путь>::<символ>` — каждое объявление Go-файла с этим именем (`Func`, `Type`, `Type.Method`,
  `Type.Field`, голое имя) от докблока до конца строками `show` с адресами; объявления нет — код 1.
- `catnip show <путь> --outline` — строка имени каждого объявления Go-файла с адресом: функции, методы, типы, поля,
  переменные и константы.
- Не-Go файл у `def`, `show ::` и `show --outline` — код 1 и `no navigation in "<ext>" files: catnip knows Go (.go)`.
- Недописанный Go-файл (синтаксическая ошибка) отвечает объявлениями, которые разобрал парсер; agent-lsp v0.5.1.

## v0.4.1

- `catnip show -C0`: значение `-C` слитно с флагом.

## v0.4.0

- `catnip def`: где объявлен символ Go — по позиции `путь:строка`, `путь:строка:колонка` или адресу `путь:N#hash` с
  выражением со строки либо по имени (`pkg.Func`, `Type.Method`, голое имя). Ответ — докблок и сигнатура, с `--body` —
  объявление целиком, строками `путь:N#hash: текст`; несколько вопросов в одном вызове, вопрос без ответа даёт код 1
  и цитату текущей строки, остальные отвечены. Разрешение по типам — библиотека
  [agent-lsp](https://github.com/hakastein/agent-lsp), кэш индекса — в каталоге кэша пользователя.
- `catnip show <путь>:<строка>#<хеш>` — окрестность строки по адресу из ответа `def` или `show`; изменившаяся строка —
  ошибка с её текущим текстом, код 1.

## v0.3.1

## v0.3.0

- `catnip show` печатает у каждой строки адрес `<номер>#<хеш>`; `--gutter line` оставляет номер, `--gutter none` —
  только текст. Флаг `--hash` убран.
- `catnip edit --after LINE#HASH NEW` и `--before LINE#HASH NEW` вставляют целые строки после или перед строкой, хеш
  которой сверяется.
- `catnip stats` — локальный HTTP-отчёт до Ctrl+C вместо HTML-файла, `--days` убран: дашборд с экранами обзора,
  проекта и его рабочих деревьев, группы ошибок, команды, файла и вызова, тёмной и светлой темой, без внешних
  зависимостей.
- Статистика пишет текст ошибки и её группу, проект — основное рабочее дерево git, worktree, ветку и применённый
  конфиг; таблицы `flags` нет. Схема новая: базу `catnip/stats.db` прежней версии удалить.
- В связанном git worktree без своего `.catnip.json` действует конфиг основного рабочего дерева с корнем в worktree.
- Справка по уровням: `catnip help` — что делает каждая команда, её синтаксис и все правки `edit`;
  `catnip <команда> --help` и `catnip help <команда>` — все флаги одной команды. Ошибка аргументов печатает строку
  ошибки и справку своей команды.
- Ошибка разбора правки `edit` повторяет саму правку, как она передана: `--replace "" "b": OLD, the text to find, is
  empty; OLD goes first, NEW second`; длинный текст обрезан до 40 символов.

## v0.2.0

- Статистика вызовов: каждый вызов catnip пишется в локальную SQLite-базу `catnip/stats.db` в каталоге конфигов
  пользователя — команда, каталог, файл, корни git и catnip, код выхода, `argv`, распознанные флаги.
- `catnip stats [--days N]`: HTML-отчёт по базе — вызовы по дням, проекты, каталоги, коды выхода, флаги, упавшие
  вызовы с `argv`, несуществующие команды.
- Бинарник — около 9 МБ: SQLite на чистом Go.

## v0.1.0

Первый выпуск.

- `catnip show`: файл, диапазон или окрестность позиции `путь:строка[:колонка]` с номерами строк; `--hash` — хеш
  строки для правки по адресу, `--blame` — git blame по строкам.
- `catnip edit`: любое число правок одного файла `--replace OLD NEW [--count N]` и `--lines FROM#HASH[-TO#HASH] NEW`,
  все или ни одной; отчёт по каждой несошедшейся правке с похожими строками.
- `catnip write`: файл из stdin; перезапись сохраняет BOM, окончания строк и перевод строки в конце.
- Фиксеры и проверки по glob из глобального конфига и ближайшего к файлу `.catnip.json`, вывод
  `<имя>: passed|fixed|failed`, `--show-fix-diff`.
- Атомарная запись с сохранением прав и симлинков; коды выхода 0/1/2/3.
- Бинарники под Linux, macOS и Windows, amd64 и arm64.

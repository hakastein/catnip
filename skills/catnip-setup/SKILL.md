# Настройка catnip в проекте

Результат — `.catnip.json` в корне проекта: на каждый язык, который в проекте правят руками, — фиксеры и проверки,
которыми проект уже пользуется, и каждая команда проверена на настоящем файле. Формат конфига — раздел «Конфиг» в
[README](https://github.com/hakastein/catnip#конфиг).

## 1. Инструменты проекта

Языки — по `git ls-files`, без сгенерированного и вендорного кода. Инструменты — из того, что проект запускает сам:
CI, `Makefile` и другие таск-раннеры, скрипты `package.json` и `composer.json`, `pyproject.toml`, pre-commit,
конфиги инструментов (`.golangci.yml`, `.eslintrc*`, `.prettierrc*`, `.php-cs-fixer*`, `phpstan.neon`, `ruff.toml`
и подобные). Вызов берётся тот, что у проекта: его бинарник (`vendor/bin`, `node_modules/.bin`), его конфиг и
версия.

Язык, для которого у проекта инструментов нет, получает только встроенную проверку синтаксиса, которая не пишет
файлов (`php -l`), если она есть; остальное — предложение пользователю в отчёте.

Прочитай глобальный конфиг `catnip/config.json` в каталоге конфигов пользователя, если он есть: его правила тоже
выполняются на файлах проекта.

Готово, когда у каждого языка есть список инструментов с источником (`путь:строка`) или пометка «у проекта нет».

## 2. Команда на один файл

catnip выполняет команды после каждой записи файла: через `sh -c` в корне проекта, `{file}` — путь от корня в
кавычках. Сначала все фиксеры, потом все проверки; внутри — по glob, внутри glob — по имени, по алфавиту.

- Фиксер меняет файл (`gofmt -w {file}`, `prettier --write {file}`); проверка его не меняет. Инструмент, который
  чинит и падает на неисправимом (`eslint --fix`, `ruff check --fix`), — один фиксер: его падение выводится как
  `<имя>: failed`. Если порядок фиксеров важен, его задают их имена.
- Инструмент, который работает на пакет, а не на файл, запускается на пакет файла:
  `cd "$(dirname {file})" && go vet .`.
- Команда, которой на файл нужно больше 5 секунд (замерь `time`), в конфиг не входит: она запускалась бы после каждой
  правки. Её место — в отчёте как команда для запуска руками.
- Имя команды — имя инструмента (`gofmt`, `phpstan`): агент видит его в выводе `<имя>: passed|fixed|failed`.
- Glob без `/` сравнивается с именем файла на любой глубине (`*.go`); glob с `/` — с путём от корня, и `*` не
  переходит `/`: `src/*.go` не берёт `src/x/a.go`. Ни `{a,b}`, ни `**` нет: на каждое расширение свой glob. Каталог
  glob'ом не исключить — применяются все подходящие glob'ы; исключения задаёт конфиг самого инструмента, как их
  видит и CI.
- Подпроект со своими инструментами (каталог с отдельным `package.json` или `composer.json`) получает свой
  `.catnip.json` в своём корне: catnip берёт ближайший к файлу конфиг целиком, `{file}` и команды — от его каталога.
- Правило проекта с тем же glob, что в глобальном конфиге, заменяет глобальное, с другим glob выполняется вместе с
  ним. Правило `{}` отключает глобальное с тем же glob.

## 3. Запись и проверка

Запомни `git status --short` до начала. Запиши конфиг: `catnip write .catnip.json`; существующий дополняется
правкой `catnip edit`, его правила сохраняются. Код 2 у следующей команды catnip — конфиг не разобрался, ошибка
называет место; удали `.catnip.json` и запиши его заново.

Затем на каждый glob:

1. Файл проекта под этим glob без локальных изменений (`git status --porcelain -- <файл>` пуст):
   `catnip write <файл> < <файл>` — содержимое то же, правила выполняются. Ждём `<имя>: passed` у каждой команды и
   код 0. Пустой вывод — glob файл не взял.
   - `fixed` — фиксер форматирует не как проект: подбери вызов, после которого файл не меняется, или убери фиксер;
     файл верни `git checkout -- <файл>`.
   - `failed` с `not found` — инструмент вызван не так, как его ставит проект.
   - `failed` с настоящим нарушением в файле — возьми другой файл; код проекта ради конфига не правится.
2. Новый файл рядом с настоящими, с именем под glob и синтаксической ошибкой: стилевую ошибку фиксер исправит
   молча. `catnip write <каталог>/<имя>`: ждём `<имя>: failed` у каждой проверки и код 3. Пробный файл удали.

Готово, когда каждая команда дала `passed` на настоящем файле, каждая проверка — `failed` на пробном, а
`git status --short` отличается от запомненного только `.catnip.json`.

## 4. Отчёт

Пользователю: таблица «glob → имя → команда → источник», правила глобального конфига, что не вошло и почему,
предложения для языков без инструментов. Коммитить ли `.catnip.json`, решает пользователь; незакоммиченный конфиг
основного рабочего дерева действует и в его git worktree.

# Настройка catnip в проекте

Результат — `.catnip.json` в корне проекта: на каждый язык, который в проекте правят руками, — фиксеры и проверки,
которыми проект уже пользуется, и каждая команда проверена на настоящем файле. Формат конфига — раздел «Конфиг» в
[README](https://github.com/hakastein/catnip#конфиг).

## 1. Инструменты проекта

Языки — по `git ls-files`, без сгенерированного и вендорного кода. Инструменты — из того, что проект запускает сам:
CI, `Makefile` и другие таск-раннеры, скрипты `package.json` и `composer.json`, `pyproject.toml`, pre-commit,
конфиги инструментов (`.golangci.yml`, `.eslintrc*`, `.prettierrc*`, `.php-cs-fixer*`, `phpstan.neon`, `ruff.toml`
и подобные). Вызов берётся тот, что у проекта: его бинарник (`vendor/bin`, `node_modules/.bin`), его конфиг и
версия.

Язык, для которого у проекта инструментов нет, получает только встроенную проверку синтаксиса языка (`php -l`,
`python -m py_compile`), если она есть; остальное — предложение пользователю в отчёте.

Готово, когда у каждого языка есть список инструментов с источником (`путь:строка`) или пометка «у проекта нет».

## 2. Команда на один файл

catnip выполняет команды после каждой записи файла: через `sh -c` в корне проекта, `{file}` — путь от корня в
кавычках. Сначала фиксеры, потом проверки.

- Фиксер меняет файл (`gofmt -w {file}`, `prettier --write {file}`); проверка его не меняет. Инструмент, который
  чинит и падает на неисправимом (`eslint --fix`, `ruff check --fix`), — один фиксер: его падение выводится как
  `<имя>: failed`.
- Инструмент, который работает на пакет, а не на файл, запускается на пакет файла:
  `cd "$(dirname {file})" && go vet .`.
- Проверка всего проекта, которая идёт дольше нескольких секунд, в конфиг не входит: она запускалась бы после каждой
  правки. Её место — в отчёте как команда для запуска руками.
- Имя команды — имя инструмента (`gofmt`, `phpstan`): агент видит его в выводе `<имя>: passed|fixed|failed`.
- Glob без `/` сравнивается с именем файла на любой глубине (`*.go`); glob с `/` — с путём от корня, и `*` не
  переходит `/`: `src/*.go` не берёт `src/x/a.go`. Каталог glob'ом не исключить — применяются все подходящие glob'ы;
  исключения задаёт конфиг самого инструмента, как их видит и CI.
- Глобальный конфиг (`catnip/config.json` в каталоге конфигов пользователя): правило проекта с тем же glob заменяет
  глобальное, с другим glob выполняется вместе с ним. Правило `{}` отключает глобальное с тем же glob.

## 3. Запись и проверка

Запиши конфиг: `catnip write .catnip.json`; существующий дополняется правкой `catnip edit`, его правила
сохраняются. Затем на каждый glob:

1. `catnip write <файл> < <файл>` на существующем файле проекта: содержимое то же, правила выполняются. Ждём
   `<имя>: passed` у каждой команды и код 0. `fixed` — фиксер форматирует не как проект: подбери вызов, после
   которого файл не меняется, или убери фиксер; изменённый файл верни `git checkout -- <файл>`. `failed` с
   `not found` — инструмент вызван не так, как его ставит проект.
2. Новый файл с ошибкой, которую ловит каждая проверка, рядом с настоящими (`catnip write <каталог>/catnip_probe.<ext>`):
   ждём `<имя>: failed` у каждой проверки и код 3. Пробный файл удали.

Готово, когда каждая команда дала `passed` на настоящем файле, каждая проверка — `failed` на пробном, а `git status`
показывает только `.catnip.json`.

## 4. Отчёт

Пользователю: таблица «glob → имя → команда → источник», что не вошло и почему, предложения для языков без
инструментов. Коммитить ли `.catnip.json`, решает пользователь; незакоммиченный конфиг основного рабочего дерева
действует и в его git worktree.

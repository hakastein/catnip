# catnip

`catnip` читает и правит файлы одной bash-командой и сцепляется через `&&`. Используй его вместо `sed -n`, `cat -n`,
`sed -i`, heredoc в файл и python-скриптов с `str.replace`.

## Просмотр

```bash
catnip show src/a.php              # весь файл с номерами строк
catnip show src/a.php:40-80        # диапазон
catnip show src/a.php:57           # позиция и 5 строк вокруг; -C N меняет окрестность
catnip show src/a.php:57:12        # позиция с колонкой, как её печатают инструменты на LSP
catnip show --hash src/a.php:40-80 # хеш строки: 57#a3f0 — адрес для правки по строке
catnip show --blame src/a.php:57   # коммит, автор и дата каждой строки
```

Строки и колонки с 1. Диапазон за концом файла — ошибка с реальным числом строк.

## Правка

Один файл, любое число правок, всё или ничего:

```bash
catnip edit src/a.php \
  --replace '$total = $price * $qty;' '$total = $price * $qty * (1 - $discount);' \
  --replace 'oldName(' 'newName(' --count 2 \
  --lines 57#a3f0-59#0b1c '        return null;' \
  && make test
```

- `--replace OLD NEW` — заменить точный текст, он может быть частью строки или несколькими строками. Текст должен
  найтись ровно один раз, с `--count N` сразу после — ровно N раз (заменяются все).
- `--lines FROM#HASH[-TO#HASH] NEW` — заменить целые строки по адресам из `show --hash`. Если крайняя строка
  диапазона изменилась, правка отклоняется; середину диапазона catnip не сверяет. Когда важно, что весь блок не
  менялся, используй `--replace` с его полным текстом.
- Пустой `NEW` удаляет. Вставка — это замена соседнего текста на него же плюс новый текст.
- Все правки адресуют исходное содержимое файла: номера строк из `show` действуют для всей команды; пересекающиеся
  правки — ошибка.
- Если хоть одна правка не сошлась, файл не пишется, а ошибка называет причину: строки совпадений, первую строку,
  на которой многострочный текст разошёлся с файлом, или похожие строки.
- Текст — обычные аргументы shell: в одинарных кавычках `$`, `\` и переводы строк идут как есть, а сама `'`
  пишется как `'\''`.

После записи catnip печатает изменённые строки (`путь:строка`, `-`/`+`) и запускает фиксеры и проверки из конфига:
изменения фиксеров показаны diff'ом, каждая прошедшая проверка — строкой `<имя>: passed`, упавшая — `<имя>: failed`
и своим выводом. Если сменились
BOM или окончания строк, это сказано отдельной строкой.

## Новый файл

```bash
catnip write src/new.go <<'EOF'
package x
EOF
```

Перезапись существующего файла сохраняет его BOM, окончания строк и наличие перевода строки в конце.

## Коды выхода

| Код | Значение |
|---|---|
| 0 | записано, проверки прошли |
| 1 | ничего не записано |
| 2 | ошибка аргументов или конфига |
| 3 | записано, но проверка упала или файл записан не целиком |

## Проблемы с catnip

catnip ещё не выпущен. О каждой проблеме с ним обязательно сообщи пользователю в ответе отдельным пунктом
«catnip:» с командой, её выводом и тем, что ожидалось. Проблема — это ошибка или падение, неверный или непонятный
вывод, правка, которую не удалось выразить, и любой обход catnip через `sed`, `python` или heredoc.
